# Frontend Audit — FinCopilot 2.0

**Date:** 2026-07-04 · **Scope:** `frontend/` (Next.js 14 App Router, TypeScript, Tailwind, shadcn/ui, Clerk) · **Method:** full read of all 40 source files, cross-referenced usage via grep, `npx tsc --noEmit` (passes clean). Report-only; no code changed.

All file paths are relative to `frontend/`.

---

## TLDR

1. **Sources are never shown to the user.** `MessageBubble.tsx:105` requires `!isStreaming` to render `SourceList`, but the `sources` prop is only ever passed to the streaming bubble (which always has `isStreaming={true}`), and settled messages loaded from the DB have no sources field. The entire `sources` SSE → `SourceList` pipeline is dead UI — for a financial research tool, citations silently never appear.
2. **A dropped or stopped stream silently destroys the partial response.** If the SSE stream ends without a `done` event (proxy timeout, backend crash) or the user clicks Stop, the accumulated text vanishes with no error and messages are never reloaded (`useStream.ts:104–181`, `app/(shell)/chat/[id]/page.tsx:57–79`). There is also no abort on unmount/conversation switch, so an in-flight stream keeps running in the background and its stale `onDone` closure can call `load()` with the *old* conversation id.
3. **No `error.tsx`, `global-error.tsx`, `loading.tsx`, or `not-found.tsx` exists anywhere in `app/`** — any uncaught render error produces Next's unstyled default crash screen; the only error boundary in the app is the one around Recharts.
4. **Every SSE token re-renders the entire transcript.** `MessageBubble` is not memoized, so each token re-runs ReactMarkdown parsing for every settled message (`MessageList.tsx:60–62`) — noticeable jank on long conversations, compounded by the always-animating pipeline tracker.
5. **The `SseEvent` type in `lib/types.ts:102` contradicts the actual wire format** (`sources` event carries `data.chunks` per `useStream.ts:134`, the type says `data.sources`; `tool_call` shapes also disagree), and it's never imported — the one place the SSE contract is written down is wrong and unused, while the real parser runs on unchecked `as` casts.

## What's solid

- **Auth is correctly enforced despite the minimal middleware.** The one server-side gate that matters exists and is right: `app/(shell)/layout.tsx:7–8` awaits `auth()` and redirects, covering every shell route (`/chat`, `/chat/[id]`, and the two disabled stubs, which sit inside the same group so even the redirects are auth-gated); `app/page.tsx:5–11` does the same at the root. `middleware.ts` runs bare `clerkMiddleware()` purely for auth context, matching the documented Edge-runtime constraint. One standing caveat to document for future work: protection lives in the *route group layout*, so any page added outside `(shell)` must remember its own `auth()` call.
- **No HTML injection surface.** Zero `dangerouslySetInnerHTML`/`innerHTML` in the codebase; AI output goes through ReactMarkdown *without* `rehype-raw`, so embedded HTML stays inert, react-markdown's default URL transform strips `javascript:` hrefs, and custom links add `rel="noopener noreferrer"` (`MessageBubble.tsx:139–144`).
- **No secret leakage.** `.env.local` is untracked; the only `NEXT_PUBLIC_` vars are the Clerk publishable key and the API base URL, both public by design.
- **Strict TypeScript, clean.** `strict: true`, `npx tsc --noEmit` passes, and there is not a single `any`, `as any`, or `@ts-ignore` in app code (the SSE `as`-casts flagged above are the whole story).
- **The hidden pages ship no client JS.** `components/portfolio/*` and the memories code are imported by nothing reachable, so the bundler drops them; the redirect stubs are 5-line server components. Clean approach.
- **Deliberate stale-closure hygiene where it counts:** `streamingContentRef` in the chat page (`page.tsx:35`), `filesRef` in `InputBar` with a documented rationale, the `cancelled` flag in `DocumentPanel`'s effect, and interval cleanup in `DocumentIngestionBanner`.
- **SSE chunk parsing is correct** — buffer split on `\n\n` with the remainder carried over (`useStream.ts:107–109`) handles events fragmented across network chunks; no cross-chunk race there.
- **Good empty/progress states:** empty chat, empty sidebar, empty document panel, per-file client-side validation with friendly messages, live ingest progress in the input bar, and mapped human-readable HTTP/SSE errors (`useStream.ts:191–224`).
- **`ChartErrorBoundary`** (`ChartBlock.tsx:30–47`) is exactly the right instinct — malformed chart data degrades to "Chart unavailable" instead of crashing the transcript. The rest of the app deserves the same treatment (see finding #4).
