# Prioritized Audit Backlog — FinCopilot 2.0

**Date:** 2026-07-05 · **Inputs:** the five audits in `docs/audits/` (frontend, backend, agent-pipeline, security, infra), all dated 2026-07-04/05.
**Method:** consolidation only — no code was re-audited. Duplicate/overlapping findings are merged into single entries with all source reports credited. Tightly related small findings from one report are bundled where they'd ship as one change.

**Scoring:** Impact 1–5 (how much it hurts if left alone) · Risk 1–5 (likelihood/severity of it actually biting) · Effort 1–5 (5 = hardest). **Priority = (Impact + Risk) × (6 − Effort)** — so a painful, likely, *easy* fix outranks a painful, likely, hard one.

## TLDR — fix these 5 before any new feature work

1. **Ingestion durability: temp-file leak + non-restart-safe Celery** (P45 + P27, backend + infra). Every successful upload leaks its file to disk forever (`ingestion.py:355-359` — cleanup condition inverted), and every Railway deploy SIGKILLs in-flight work (PID-1 bash, no `trap`; no `task_acks_late`; ingestion not idempotent), stranding documents in `processing` permanently. This is a slow-motion disk-full outage *and* silent data loss on the exact pipeline Portfolio Chat will sit on. The pieces interlock — ship as one PR.
2. **Retrieval metadata filter mismatch** (P40, backend). `_apply_filters` reads `ticker`/`fiscal_year`; the ingestion side writes `doc_ticker`/`doc_filing_date` and nothing ever writes `fiscal_year`. Any filtered agent step gets **zero chunks, silently** — the core product (grounded answers) is quietly broken for a whole class of queries, and the fix is a key rename plus one test.
3. **Upload OOM + zero rate limiting** (P36 + P32, backend + security). Both upload paths `await file.read()` the entire body into RAM *before* the size check, on a 1 GB container that also hosts the Celery worker; and no endpoint has any per-user quota. One signed-up user — malicious or just enthusiastic — can OOM-kill the whole backend or drain the OpenAI budget. This is the security audit's #1 real-world risk.
4. **Cross-tenant write on `/documents/upload`** (P35, backend + security). The one authorization hole in an otherwise well-isolated multi-tenant financial app: any authenticated user can attach documents to any conversation UUID (pollution + existence oracle, not disclosure). The correct check already exists in `chat.py:557-571` — this is a copy-paste-sized fix to close an entire vulnerability class.
5. **Synthesizer prompt selection buries tool results** (P32, agent). When a turn produces both RAG chunks and tool results, the RAG prompt wins and instructs the model to use *only* the chunks — reproducing the user-visible symptom of the previously-fixed "tool results ignored" bug through a new mechanism. Wrong answers with the right data in context, on exactly the complex queries the product is for.

Why these five: #2–#5 are all effort ≤2, and together with #1 they cover the four ways this app can fail its users — lose their data (1), silently give wrong answers (2, 5), fall over (3), and cross tenant lines (4). Everything else is degradation; these are broken.

## Phased plan

Phases are judgment-ordered, not strictly score-ordered: cheap high-score fixes first, then the reliability groundwork Portfolio Chat depends on.

### Phase 1 — This week (all effort 1–2; mostly one-liners to small PRs)

1. **Ingestion durability PR** (interlocking, ship together): delete temp file on success/terminal failure; `task_acks_late=True` + `worker_prefetch_multiplier=1` + task time limits; idempotent chunk insert (delete-then-insert or unique `(document_id, chunk_index)`); `trap`/`wait` in `start.sh`; sweep for documents stuck in `processing`. *(TLDR #1)*
2. **Retrieval filter key fix** + a test that filtered retrieval over known metadata returns rows. *(TLDR #2)*
3. **Ownership check on `/documents/upload`** — reuse the `chat.py` query. *(TLDR #4)*
4. **Kill the hot-path blockers**: offload Tavily (pattern exists in `news_fetch`), make LangSmith lookup fire-and-forget after `done`, skip when key empty, drop the 1 s sleep.
5. **Fix local Compose**: remove the second worker service, standardize one settings-driven upload dir.
6. **Small correctness wins**: EDGAR limiter in `_sec_route`; planner/tool_selector parse failure → degrade to LLM-only; subscribe-before-enqueue in document_finder; wrap `call_next` in logging middleware; sanitize `str(e)` on the wire; align concurrency config; `.dockerignore` + rotate the on-disk keys.
7. **Frontend safety net**: add `error.tsx`/`global-error.tsx`; wire the installed alert-dialog for conversation delete.

### Phase 2 — Before Portfolio Chat ships

Reliability and answer-quality groundwork the new feature will inherit:

- **Availability/abuse**: stream uploads to disk in bounded chunks with one settings-driven limit + file-count cap; per-user Redis token bucket on stream + upload; magic-byte sniffing and page/parse caps in ingestion. *(TLDR #3)*
- **Answer correctness**: fix synthesizer prompt selection for mixed chunk+tool turns *(TLDR #5)*; add the anti-fabrication clause to all prompts and address the 4 000-char truncation; delimit untrusted content with a do-not-follow-instructions guard — then run the three live NV tests the agent audit specifies (injection, fabrication-past-truncation, citation fidelity).
- **Sources UI**: persist sources with the assistant message and render them on settled messages — citations are table-stakes for a financial research tool and Portfolio Chat will need the same pipeline.
- **Frontend stream lifecycle**: handle EOF-without-done (treat as error + reload messages), keep/reload the partial on Stop, abort on unmount/switch; validate SSE payloads against a corrected `SseEvent`; route `sendConfirmation` through `useStream`.
- **Ops floor**: real health check (DB ping, Redis ping, worker heartbeat; exit non-zero when a child dies); Railway backups + scheduled `pg_dump` + **one restore drill**; Sentry + external uptime check; promote lifecycle logs to INFO and bind user/conversation/request correlation; audit Railway env vars (`APP_ENV` etc.) with a boot log of resolved config; migration drift check at startup.
- **Remaining security/mediums**: bind HIL tokens to user+conversation and move the branch after the ownership check; make `year` required for 10-K/10-Q; paginate list endpoints; migrate python-jose → PyJWT; webhook poison-message fix; model allowlist.
- **Frontend polish that affects daily use**: memoize `MessageBubble`; surface message/sidebar load errors; keyboard access for conversation rows + focus-visible delete (the a11y bundle's high-value half).

### Phase 3 — Can wait (do opportunistically or when triggers fire)

- **Triggered by scale/plan changes**: `_build_chunks` streaming refactor + the 2 GB / reranker decision (do the chunker fix *before* re-enabling reranker or concurrency=2); HNSW post-filter `EXPLAIN ANALYZE`; unbounded-conversation pagination tuning; `worker_max_tasks_per_child`.
- **Triggered by touching the area anyway**: drop the duplicate HNSW index; throttle auth's per-request write; auth `azp`/issuer pin; SSRF host-blocking; torch → optional extra; router word-boundary matching; skip redundant executor retrieval; portfolio_analysis retry; citation post-check; migration README documenting the numbering gap + irreversibility + dump-before-upgrade rule.
- **Cosmetic/hygiene**: remaining a11y items (aria-live, color-only cells, banner palette/contrast); ComparisonTable → markdown renderers; Recharts dynamic import; Clerk version pin/theming consolidation; DocumentPanel refresh; both dead-code bundles; `.gitignore` re-encode; delete `requirements.txt`; regenerate `.env.example`; `NEXT_PUBLIC_API_URL` assert; CORS preview regex (or document previews as frontend-only); `predev` kill-port; stale restore comments.

**Explicitly not planned** (audits confirm these are deliberate, not bugs): single-container merge, `--concurrency=1`, `RERANK_ENABLED=False`, removed evaluator/financial_calculator, router keyword override existing at all, fixed port 8000.
